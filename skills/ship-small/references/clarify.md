# Resolve only consequential ambiguity

Identify the actor, current task, input, desired output, and observable success. Resolve answers from supplied context, README, code, and earlier responses before asking. If missing answers change the data contract, permissions, irreversible action, or acceptance behavior, batch the few related consequential questions in one concise message with concrete options. Avoid serial one-question round trips. Clear small tasks need no interview; otherwise state reversible assumptions and implement independent work.

If an actual stakeholder is available and the workflow is unclear, ask about a recent real example, the painful step, an exception, and what would count as done. Use only answers actually supplied. Stop interviewing once the next implementation decision is clear.

Turn the answer into one acceptance example: given input X, action Y produces observable Z. Keep optional ideas outside the first slice. Do not invent business requirements.
